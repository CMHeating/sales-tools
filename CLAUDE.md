# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

CM Heating Sales Operations Hub — a collection of static HTML tools for the sales team (HCAs: Home Comfort Advisors) at CM Heating, an HVAC company in Everett, WA. Tools cover follow-up tracking, leaderboard display, quoting, scheduling, and install availability.

Live deployments:
- GitHub Pages: `https://cmheating.github.io/sales-tools/` (most tools)
- Firebase Hosting: `https://install-availability-tracker.web.app/` (Install Availability only)

## Architecture

**Most tools are single self-contained HTML files** with all CSS and JS inline. No build step, no npm, no bundler — just edit and commit.

**Install Availability Tracker** is the exception: it has a build pipeline and Firebase backend.

- Source: `install-availability.html` — development version (not for direct production use). `ADMIN_PINS` and `HCA_PINS` are empty here on purpose; real PINs live in `pin-config.private.json` and are injected by the build.
- Production: `install-availability-secure.html` — generated by the build script (do not edit directly)
- Firebase Realtime Database paths: `cmh_schedule`, `cmh_availability`, `cmh_edit_locks`, `cmh_audit_logs`
- Firebase project: `install-availability-tracker`

## File Routing

Which rules apply to a file, by path. These are the repo's existing conventions in one place — the sections below give the detail.

| Pattern | Rule |
|---|---|
| `install-availability.html` | Build input. After editing, run the build (below) from the repo root — the secure tracker is now stale. |
| `scripts/install-availability-users.spark.js` | Roster. Edit here to add/remove users, then rebuild **and** redeploy the database rules. |
| `install-availability-secure.html` | **Generated — never edit.** Hand-edits are overwritten by the next build. |
| `database.install-availability.spark.rules.json` | **Generated — never edit.** Same build script. |
| `*.before-*.html` | **Frozen recovery snapshots.** Never edit or delete. Creating a new one before a risky change is encouraged. |
| `*.private.*`, `firebase-hosting-install/`, `firebase.*-only.json` | Secrets and local deploy scaffolding — gitignored, never commit. |
| Any committed file | No PIN literals. Everything outside the ignore list is published to GitHub Pages. |
| New `*.html` tool | Self-contained (inline CSS/JS, no build), matches the dark theme, and gets a link added to `index.html`. |

Both `scripts/build-install-availability-spark.js` and `scripts/extract-install-pins.js` resolve their inputs relative to the working directory, so run them from the repo root.

### Guard hook

`scripts/claude-guard.js` enforces the three rules above that are easy to lose track of mid-task — generated files, snapshots, and PIN literals — and reminds you to rebuild after a build input changes. It is wired up in `.claude/settings.json` as a `PreToolUse`/`PostToolUse` hook on the editing tools.

It fails open by design: any parse error or unexpected input lets the tool call through. Set `CMH_GUARD_OFF=1` to disable it for a session.

## Install Availability Build Pipeline

The secure tracker is built from the source file plus the user roster:

```bash
node scripts/build-install-availability-spark.js
```

This reads `install-availability.html` + `scripts/install-availability-users.spark.js` and outputs:
- `install-availability-secure.html` (deploy to Firebase Hosting)
- `database.install-availability.spark.rules.json` (deploy to Firebase Realtime Database)

To add/remove users, edit `scripts/install-availability-users.spark.js`, then rebuild.

See `INSTALL-AVAILABILITY-SECURITY.md` for full deploy commands (Hosting, Database rules, emergency rollback).

## Firebase Auth Users

After enabling Email/Password auth in Firebase console:

```bash
node scripts/create-install-auth-users-spark.js
```

Good output: `CREATED` or `EXISTS_OK` per user, then `Auth users ready.`

## Backup File Convention

Many `.before-xxx.html` files exist as named snapshots before significant changes (e.g., `install-availability.before-slot-locks.html`). Leave these in place — they are intentional recovery points, not clutter.

## Design Patterns

All tools share a consistent dark theme — navy/dark blue backgrounds (`#0a1628`), orange accent (`#f58220` / `#c97d10`), white text, IBM Plex or Outfit fonts. New UI should match this visual language.

The Leaderboard and Install Availability tools use Firebase JS SDK v10 loaded via CDN (`https://www.gstatic.com/firebasejs/10.12.0/`). All other tools are pure client-side with no external dependencies beyond Google Fonts.

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.
